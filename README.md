# Risu Krea2 Integration

PocketRisu 삽화 모듈과 Krea2 전용 ComfyUI 워크플로를 연결하는 재현용 저장소입니다.

이 저장소에는 다음 항목만 기록합니다.

- PocketRisu Krea2 삽화 모듈
- Krea2 장수 검증 재시도를 보장하는 LightBoard 백엔드 모듈
- Krea2 + FlashAttention + fedor_bypass 워크플로
- 프리셋별 캐릭터 매칭·일괄 LoRA 라우팅을 위한 Hooking Manager 패치
- 모듈과 워크플로 빌더, 테스트, 설치 문서

ComfyUI 본체, Python 런타임, 모델 파일, LoRA 파일, 생성 이미지, 로그와 로컬 설정은 포함하지 않습니다.

## 현재 동작

1. 모듈이 장면마다 중심인물 1명과 필요한 보조인물 최대 2명을 구성합니다.
2. Hooking Manager가 원본 Krea2 워크플로의 Power LoRA Loader에서 파일명과 강도를 읽습니다.
3. 전용 메뉴에서 파일별 영문 캐릭터명과 적용 강도를 저장합니다.
4. 1인 장면에서 이름이 정확히 일치하면 해당 LoRA 하나만 적용합니다.
5. 2~3인 장면은 얼굴 전염 방지를 위해 캐릭터 LoRA 노드를 항상 제거합니다.
6. 1인 장면이라도 빈칸이거나 이름이 일치하지 않으면 캐릭터 LoRA를 적용하지 않습니다.
7. 같은 전용 메뉴에서 이미지 가로·세로 해상도를 수정하면 다음 생성 요청부터 적용합니다.
8. 프리셋마다 캐릭터 매칭, 선택 LoRA 일괄 적용, 미적용 중 하나를 선택할 수 있습니다.
9. 모듈의 `프리셋 2D`는 후킹 매니저의 식별자 `2D`와 연결됩니다.
10. 모듈에서 응답당 이미지 수, 키비주얼 포함 여부와 장면 선택 방식을 조절할 수 있습니다.

재부팅 후에는 `E:\Chatbot\Start Krea2 Chatbot.bat`를 더블클릭하면 Krea2 ComfyUI,
Hooking Manager와 PocketRisu가 함께 실행됩니다. 현재 4.4.13 모듈은 다섯 개의
개별 문단 토큰을 프리셋에서 조립하며, 실사·2D 같은 렌더링 스타일도 프리셋이
결정하도록 분리되어 있습니다. `프리셋 1`만 실사 문구를 포함하고 `프리셋 2D`는
애니메이션·만화 렌더링 문구만 포함합니다. 대화, 시선 교환, 접촉, 대치가 장면의 핵심이면
필요한 인물을 실제 구도에 포함하고, 무관한 군중은 추가하지 않습니다.

문단 길이만 부족한 응답은 전체 장면을 다시 계획하지 않고, 기존 TOON 구조와 정상
필드를 그대로 보존하면서 검증에서 지목된 문단만 보조 모델이 다시 작성합니다.
이미지 장수 보충은 삽화 모듈의 최종 출력 처리부에서 수행하므로 원본 LightBoard
3.4.0 백엔드를 그대로 사용합니다. 원본 백엔드 메뉴의 `최대 시도`를 `2`로 두면
빈 문단 같은 구조 오류가 있을 때만 기존 부분 재작성 규칙이 동작합니다.

## 모듈 출력 설정

채팅 화면에서 모듈의 **🌠삽화** 메뉴를 열어 설정합니다. 변경값은 다음 삽화 요청부터
적용되며 PocketRisu나 ComfyUI를 재시작할 필요가 없습니다.

| 설정 | 선택값 | 기본 동작 |
| --- | --- | --- |
| 생성 장수 | `자동(4~6)`, `1`~`6` | 자동에서는 보조 모델이 장면 중요도에 따라 총 4~6장을 선택합니다. 숫자를 고르면 키비주얼을 포함해 정확히 그 수를 생성합니다. |
| 키비주얼 | `자동`, `항상 포함`, `사용 안 함` | 자동에서는 서사를 대표할 장면이 있을 때만 키비주얼을 포함합니다. |
| 장면 선택 | `균형 배치`, `핵심 장면 우선`, `후반부 우선` | 균형 배치는 출력 전체에 장면을 분산합니다. |
| 키비주얼 위치 | `위`, `아래` | 키비주얼이 있을 때 전체 출력의 위쪽 또는 아래쪽에 배치합니다. |
| 저장 개수 | `1`~`20` | 이전 이미지 프롬프트 기록을 보관할 개수이며 기본값은 3입니다. |
| 엑스트라 기억 | `사용`, `사용 안 함` | 현재 채팅에서 만들어진 엑스트라의 고정 외모를 재사용합니다. 사용 안 함은 임시 기억만 삭제합니다. |
| 기억 인원 | `1`~`50` | 채팅별로 유지할 엑스트라 수이며 기본값은 20입니다. |

`1장 + 항상 포함`을 선택하면 그 한 장은 키비주얼이 됩니다. 생성 장수를 줄이면 보조
모델 호출과 ComfyUI 작업량도 줄지만, 긴 출력에서 중요한 장면이 생략될 수 있습니다.
설정값이 없거나 구버전 채팅이면 자동 4~6장, 키비주얼 자동, 균형 배치로 동작합니다.
PocketRisu가 선택 메뉴를 번호로 저장하는 규칙을 적용하므로 키비주얼과 장면 선택도
화면에 표시된 항목과 정확히 일치합니다. `사용 안 함`은 검증기와 이미지 호출 직전의
후처리 양쪽에서 키비주얼을 차단합니다.

엑스트라 기억은 `lb-xnai-extra-registry-v1` 채팅 상태에만 저장됩니다. 공식
`lb-xnai.lb.extra` 로어북은 읽기 전용이며 수정·삭제되지 않습니다. 공식 캐릭터와 이름이
겹치는 임시 기록은 거부하고, 임시 엑스트라는 캐릭터 LoRA 라우팅에서 제외합니다.
기억에는 머리, 피부, 체형, 얼굴과 영구 특징만 포함하며 의상·자세·배경은 포함하지 않습니다.

모듈 메뉴는 실제 코드에서 사용하는 발동, 이미지발동, 출력 구성, 프리셋,
키비주얼 위치와 저장 개수만 유지하며 사용되지 않는 기존 NAI 옵션은 제거했습니다.

자세한 설치와 검증 방법은 `integration/README.md`와 `hooking_manager/README.md`를 참고하세요.

## 저장소 자체 검증

모델이나 ComfyUI 설치 없이 게시된 모듈, 워크플로, 런처와 Hooking Manager 패치의 계약을 확인할 수 있습니다.

```powershell
python -m unittest discover -s integration/tests -v
```
